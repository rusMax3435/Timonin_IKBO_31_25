# Dependency Graph Visualizer (Rust/Cargo)

Инструмент визуализации графа зависимостей для менеджера пакетов.
Выполнен в рамках дисциплины "Конфигурационное управление" (Вариант №26).

## Общее описание
На данный момент реализованы все 5 этапов практической работы:
* **Этап 1:** Создано CLI-приложение с настраиваемыми параметрами, валидацией ввода и выводом конфигурации в формате ключ-значение.
* **Этап 2:** Реализована логика получения данных о зависимостях. Программа скачивает файл `Cargo.toml` из публичного GitHub-репозитория (или читает локальный файл в режиме тестирования) и извлекает список прямых зависимостей пакета.
* **Этап 3:** На данном этапе реализован алгоритм обхода в ширину (BFS) без использования рекурсии для построения транзитивного графа зависимостей. Поддерживается обработка циклических зависимостей (за счет множества `visited`). Реализован режим тестирования с помощью локального текстового файла.
* **Этап 4:** Реализован режим вывода обратных зависимостей (пакетов, которые зависят от заданного). Для этого используется алгоритм BFS, примененный к перевернутому графу.
* **Этап 5:** Инструмент генерирует код Graphviz и сохраняет изображение в PNG с помощью системной утилиты `dot`.

## Описание функций и настроек
Приложение использует стандартную библиотеку Python (`argparse`, `urllib`, `tomllib`).
Формат тестового файла: `ИМЯ_ПАКЕТА: ЗАВИСИМОСТЬ1, ЗАВИСИМОСТЬ2` (пакеты обозначаются большими латинскими буквами).

### Доступные опции командной строки
- `-p`, `--package` (обязательный) — Имя анализируемого пакета.
- `-r`, `--repo` (обязательный) — URL-адрес репозитория на GitHub или путь к локальному файлу `Cargo.toml`.
- `-t`, `--test-mode` (флаг) — Включает режим тестирования (чтение локального файла вместо запроса по сети).
- `-v`, `--version` — Версия пакета (тег в GitHub, например `1.0.0`). По умолчанию `latest` (скачивает из ветки `main` или `master`).
- `-o`, `--output` (обязательный) — Имя файла для сохранения будущего графа (с расширением `.png`, `.svg` и т.д.).

### Валидация (Обработка ошибок)
Программа проверяет:
1. Формат версии (должен быть `latest` или соответствовать `X.Y.Z`).
2. Доступность URL или наличие файла на диске (в тестовом режиме).
3. Допустимое расширение для выходного файла.

## Структура проекта
- `src/` — исходный код (`main.py`, `fetcher.py`, `parser.py`).
- `tests/` — модульные тесты.
- `run.sh` / `run.bat` / `Makefile` — скрипты для запуска.

## Сборка и запуск
Проект не требует установки зависимостей (требуется Python 3.11+ из-за встроенного модуля `tomllib`).

**Запуск через скрипты:**
* Linux/macOS: `./run.sh`
* Windows: `run.bat`

**Запуск вручную:**
```bash
python3 src/main.py -p "serde" -r "https://github.com/serde-rs/serde" -o "graph.png" -v "latest"
python src/main.py -p "ripgrep" -r "https://github.com/BurntSushi/ripgrep" -o "graph.png" -v "latest"
```
